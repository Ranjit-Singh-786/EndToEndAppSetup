# Build an End-to-End Microservices Demo Application

I want you to build a complete, runnable **end-to-end microservices demo application** that I can use to learn and demonstrate:

* Microservices architecture
* FastAPI
* Docker
* Dockerfiles
* Docker Compose
* MySQL
* MongoDB
* Frontend + backend integration
* REST APIs
* Service-to-service communication
* Shared databases / database ownership concepts
* Environment variables and configuration
* Container networking
* Health checks
* Basic production-style project structure

## 1. Project Theme

Build a **Smart Agriculture / Smart Farming Management System** called:

**SmartFarm**

The application should allow a farmer to manage farms, crops, and sensor/field data.

The application should contain at least **3 independent FastAPI microservices** that together form one complete application.

Use a simple modern frontend so that I can demonstrate the complete flow:

**Browser → Frontend → Microservices → MySQL/MongoDB**

---

# 2. Required Microservices

Create these three microservices:

## Service 1 — User/Farmer Service

Responsibility:

* Farmer registration
* Farmer login
* Farmer profile
* Basic farmer management

Use **MySQL** for persistent relational data.

Example data:

* farmer_id
* name
* email
* password_hash
* phone
* created_at

Endpoints:

```text
POST /farmers
GET /farmers/{farmer_id}
GET /farmers
PUT /farmers/{farmer_id}
DELETE /farmers/{farmer_id}
```

---

## Service 2 — Farm/Crop Service

Responsibility:

* Create farms
* Manage farms
* Add crops to farms
* View crop information

Use **MySQL** for relational data.

Example tables:

```text
farms
---------
id
farmer_id
farm_name
location
area_acres
created_at

crops
---------
id
farm_id
crop_name
crop_type
sowing_date
expected_harvest_date
status
created_at
```

Important:

`farmer_id` should reference the farmer concept from the User/Farmer Service.

Demonstrate how one microservice can consume data belonging to another service through an API rather than directly depending on the other service's application code.

Endpoints:

```text
POST /farms
GET /farms
GET /farms/{farm_id}
PUT /farms/{farm_id}
DELETE /farms/{farm_id}

POST /farms/{farm_id}/crops
GET /farms/{farm_id}/crops
GET /crops/{crop_id}
```

---

# 3. Service 3 — Farm Monitoring / Sensor Service

Responsibility:

* Store sensor readings
* Retrieve sensor readings
* Show latest field conditions
* Generate simple farm monitoring information

Use **MongoDB** for this service.

MongoDB is intentional here because sensor data is flexible and can contain different fields over time.

Example MongoDB document:

```json
{
  "farm_id": 1,
  "sensor_id": "SENSOR-001",
  "timestamp": "2026-08-12T10:00:00",
  "temperature": 31.5,
  "humidity": 62,
  "soil_moisture": 41,
  "rainfall": 0,
  "additional_data": {
    "battery": 87,
    "signal_strength": 92
  }
}
```

Do NOT force this data into MySQL.

Endpoints:

```text
POST /readings
GET /readings/{farm_id}
GET /readings/{farm_id}/latest
GET /readings/{farm_id}/summary
```

# 5. Important Microservices Architecture Requirement

I want this project to teach me the difference between:

```text
Monolithic Application
        vs
Microservices Application
```

The final architecture should approximately look like:

```text
                    ┌─────────────────┐
                    │    Frontend     │
                    │ HTML/CSS/JS     │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
      ┌─────────────┐ ┌─────────────┐ ┌──────────────┐
      │ User Service│ │ Farm Service│ │   Monitoring │
      │  FastAPI    │ │   FastAPI   │ │    Service   │
      └──────┬──────┘ └──────┬──────┘ │   FastAPI    │
             │               │         └──────┬───────┘
             │               │                │
             ▼               ▼                ▼
        ┌─────────┐     ┌─────────┐      ┌──────────┐
        │  MySQL  │     │  MySQL  │      │ MongoDB  │
        └─────────┘     └─────────┘      └──────────┘
```

However, if appropriate, use a **single MySQL container/database server** with separate databases or schemas for the MySQL-based services, while keeping MongoDB separate.

Explain the trade-off.


# 10. Environment Variables

Do NOT hard-code database credentials inside Python source code.

Create:

```text
.env
```

Use environment variables such as:

```env

MYSQL_HOST=mysql
MYSQL_PORT=3306
MYSQL_DATABASE=smartfarm

MONGODB_HOST=mongodb
MONGODB_PORT=27017
MONGODB_DATABASE=smartfarm_monitoring
```

For local development outside Docker, make sure the configuration can also support:

```text
localhost
```

as the database host.

Use Pydantic Settings or an equivalent clean configuration approach.
